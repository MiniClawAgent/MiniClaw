# 功能规划：AI 向用户提问（选择题 / 征求意见）

> 状态：**仅规划，未写任何代码**
> 日期：2026-11-16
> 参考：DeepSeek Harness 的 `@deepseek-ai/dsh-tool-ask-user`（工具契约）+ `@deepseek-ai/dsh-client-ui-user-questions`（Web 端交互）

---

## 一、一句话目标

AI 遇到**只有用户能决定**或**它猜了会做错**的事情时，可以停下来问一句，并把选项摆好；用户点一下，AI 接着干。

典型场景：

- "这三个文件要删哪几个？"（多选）
- "封面用 A/B/C 哪一版？"（单选 + 每项一句说明）
- "你的路由器管理密码是什么？"（纯文本输入）
- "要我按默认 30 天保留，还是改成 7 天？"（单选，推荐项在前）

## 二、参考实现（DeepSeek Harness）是怎么做的

### 2.1 工具契约

工具名 `ask_user_question`，入参：

```json
{
  "questions": [
    {
      "id": "cleanup",
      "question": "要清理这三个文件吗？",
      "detail": "可选：补充说明，不混进选项文字",
      "header": "确认",
      "options": [
        { "label": "删除（推荐）", "description": "移除三个过期文件" },
        { "label": "保留", "description": "中止清理" }
      ],
      "multiSelect": false
    }
  ],
  "timeout": 120
}
```

关键约定（直接抄作业的部分）：

| 约定 | 说明 |
|---|---|
| `id` 由调用方给 | 答案按 id 回传，不靠位置 |
| 推荐项排第一 | 标签里带「(Recommended)」，Web 端会默认选中它 |
| `multiSelect` | 缺省单选；多选时**所有**标了推荐的项都默认选中 |
| 返回结构 | `{ "answers": [ { "id": "...", "selected": ["标签"], "custom": "补充文字" } ] }` |
| 跳过 | `selected` 为空且无 `custom` = 用户跳过了这题 |
| 子代理 | **不能**调用（返回 `DELEGATED_CALLER`），必须把待决问题写进它的最终结果，由父级来问 |
| 无应答端 | 阻塞调用直接报错；定时调用到达 deadline 返回 `{ "pending": true, "callId": "…" }` |

### 2.2 两种模式

- **blocking（默认）**：工具一直等到用户回答，再继续。适合"不答就没法继续"。
- **timed**：带 deadline（秒），到点返回 `pending`，模型可以先去干别的；问题**仍然可答**，用户之后回答会作为一条 user 消息补进来（带 `kind/tool/callId` 便于前端配对）。

### 2.3 Web 端交互（值得学的细节）

- 卡片**临时占据输入框的位置**（不是弹窗），回答完自动让位；
- 多问题用**分页器**逐个过，可以跳过单题；最后一次性提交一批答案；
- 定时模式有倒计时；**聚焦输入框会暂停倒计时**，点「Take time」可以彻底停表；
- 卡片被关掉后不丢：那条工具行还在，点它能**重新打开**；回答过的显示只读回顾卡；
- 重启后 Host 保留问题；浏览器刷新保留**未提交的草稿**；
- 默认选项策略：单选自动选中"推荐"项，多选自动选中所有"推荐"项——**减少一次点击**。

### 2.4 它没有解决、需要我们自己想的

- 卡片抢占输入框在 iOS 上会跟输入法、附件栏打架；
- 没有"用户长时间不在"的收敛策略（它靠 timed 模式，但不是默认）；
- 没有"AI 问得太频繁"的收敛（只在 prompt 里劝）。

## 三、MiniClaw 的现状与约束

| 约束 | 影响 |
|---|---|
| 会话页是 `UICollectionView` + 行模型（triple：header / block / footer） | 问题卡最自然的位置是**再插一个 block**，而不是弹窗 |
| 已有 `ToolConfirmationBridge`：`withCheckedContinuation` + 单槽位 + 5 分钟兜底 + `cancel(sessionID:)` | 直接复刻这套骨架最省事，语义也一致 |
| 引擎有暂停 / 停止 / 检查点 / 恢复 | 问题必须能被这些动作收拾干净，不能留下悬挂的 continuation |
| 子代理是独立 `AgentLoopEngine` | 必须禁止子代理问用户（否则用户在一个看不见的会话里被问） |
| App 会被杀、会进后台 | 问题要落盘；重启后能重新显示并允许回答 |
| 本地化 4 语 | 卡片内所有文案、按钮、状态都要进 String Catalog |

## 四、推荐方案

### 4.1 分层

```
工具层  AskUserTool（模型可见）  ──┐
                                 ├─→ AskUserBroker（等待/取消/超时/并发控制）
会话层  block: .question         ──┤
UI 层   QuestionBlockView（卡片） ──┘
```

### 4.2 工具层

工具名：`ask_user`（符合新的 snake_case 约定；旧名不存在，不需要别名）。

入参（比 DSH 略保守，降低模型乱用概率）：

```json
{
  "questions": [{
    "id": "pick",
    "question": "封面用哪一版？",
    "detail": "可选补充",
    "header": "可选短标题",
    "options": [{ "label": "A 版", "description": "深色" }],
    "multiSelect": false,
    "allowCustom": true        // 新增：是否允许自由输入（默认 true）
  }],
  "timeout": 600               // 秒；0 = 一直等（默认 600）
}
```

限制（在工具里硬校验，不指望模型自觉）：

- 一次最多 **4** 个问题；每题最多 **6** 个选项；`question` ≤ 200 字、`label` ≤ 60 字；
- `id` 必须唯一且非空；
- `options` 为空时必须允许自由输入（否则这题没法答）；
- 同一会话同时只能有 **1** 个待答问题卡（第二个直接返回错误："先回答上一个问题"）。

返回给模型：紧凑 JSON 文本

```json
{"answers":[{"id":"pick","selected":["A 版"]}],"skipped":0}
```

- 用户跳过：该项 `selected: []`，另给 `skipped` 计数；工具描述里写清"跳过 = 按你的最佳判断继续，并在回复里说明你假设了什么"；
- 超时：返回 `{"pending":true,"callId":"…"}`（v1 建议直接返回错误 `{"error":"no_answer"}`，见 §7 决策点 1）；
- 用户点停止 / 离开会话 / 删除会话：返回 `{"error":"cancelled"}`；
- 子代理调用：返回 `{"error":"delegated_caller"}`，并在系统提示里要求"子代理必须把待决问题写进最终结果"。

### 4.3 会话状态层

新增一个 block 类型，而不是新消息角色：

```swift
enum AssistantBlockKind {
    case text, thinking, tool, info, question   // 新增
}
```

`question` 携带：

```swift
struct UserQuestionPayload: Codable {
    let callId: String
    var questions: [UserQuestion]
    var answers: [UserQuestionAnswer]?   // nil = 待回答
    var state: State                     // pending / answered / skipped / cancelled / expired
    var answeredAt: Date?
}
```

好处：

- 天然复用现有的行高、流式、快照、持久化（`ChatMessage.blocks` 已经是 Codable）；
- 历史会话里能看到"当时问了什么、我选了什么"；
- 重新打开会话时，待答卡还是可点的（不需要额外状态机）。

### 4.4 等待与取消

新 `AskUserBroker`（`@MainActor` 单例，照抄 `ToolConfirmationBridge` 的骨架）：

| API | 作用 |
|---|---|
| `request(payload, sessionID, callId) async -> Result` | 登记槽位 + `withCheckedContinuation` |
| `resolve(sessionID:callId:answers:)` | UI 提交时恢复 |
| `cancel(sessionID:reason:)` | 停止 / 离开 / 删除会话 / 工具超时 |
| `pending(sessionID:)` | 视图查询是否有待答卡 |
| `cancelAll()` | 极端兜底（如引擎销毁） |

**必须有终态**：沿用"5 分钟兜底"的思路，但问答的超时给到 **10 分钟**（可配置），到点自动按"跳过"处理并告诉模型。

接入点：

- `AgentLoopEngine.cancel()` / `pause()`：调 `cancel(sessionID:)`；
- `SessionManager.deleteSession`：同 `revokeSession` 那样联动；
- `ChatView` 离开会话（`onDisappear`）：**不取消**（用户可能只是去看设置），但停止/删除要取消。

### 4.5 UI 层

**卡片长在消息流里**，不做"抢占输入框"：

```
┌───────────────────────────────┐
│ ？ 需要你确认                  │  ← header（可选）+ 状态
│                               │
│ 封面用哪一版？                 │  ← question
│ 深色版适合夜间阅读              │  ← detail（次要色）
│                               │
│ ┌───────────────────────────┐ │
│ │ ● A 版   深色（推荐）      │ │  ← 单选；推荐项默认选中
│ │ ○ B 版   浅色              │ │
│ └───────────────────────────┘ │
│                               │
│ [ 自己输入…            ]       │  ← allowCustom
│                               │
│ [跳过]              [提交答案] │
└───────────────────────────────┘
```

交互细节：

1. **多题分页**：`第 1/3 题` + 左右箭头；最后一题按钮变"提交"；
2. **多选**：方框勾选；推荐项默认勾上；
3. **已回答**：卡片折叠成一行 `✓ 你选择了：A 版`，点开可看完整问答（只读）；
4. **跳过**：单题跳过 → 换下一题；最后一题跳过 → 提交并标记该题 empty；
5. **超时**：卡片变灰，显示"已等待超时，AI 已按默认继续"，仍可回答（回答后作为补充消息）；
6. **滚动**：新问题卡出现时，若不在视口内，在输入框上方显示一条**胶囊提示**「有一个问题等你回答」，点击滚过去——比强制跳转温和；
7. **无障碍**：选项用 `.accessibilityAddTraits(.isSelected)`，卡片整体一个 VoiceOver 分组；
8. **本地化**：所有文案走 String Catalog（4 语）。

### 4.6 什么时候允许问（prompt 约束）

系统提示里加一段（照 DSH 的措辞）：

> 只在**用户自己的选择**或**无法通过查看代码/文件解决的歧义**时使用 `ask_user`。
> 能自己查清的事实不要问；一次最多问 4 个问题；推荐项放第一个并在标签里标注"（推荐）"。
> 子代理不能直接问用户，必须把待决问题写进最终结果。

再加一条 MiniClaw 特有的：

> 用户明确要求"别问我、你自己决定"时，不要调用该工具。

### 4.7 与暂停 / 停止 / 恢复的关系

| 动作 | 行为 |
|---|---|
| 用户点暂停 | 问题卡保持可答；回答后**不自动继续**（暂停优先），等用户点继续 |
| 用户点停止 | `cancel` → 工具返回 cancelled，卡片变"已取消"灰态 |
| App 被杀 | 卡片随 block 落盘；重启进入会话能看到"待回答"，点提交后走现有检查点恢复续跑 |
| 用户答完 | 引擎侧 continuation 恢复 → 工具返回 → 正常继续（不需要额外 resume） |

## 五、分阶段落地

### P0（最小可用，建议先做）

- `ask_user` 工具：单问题、单选、允许文本输入、跳过、阻塞等待、10 分钟超时；
- `AskUserBroker` + 停止/删除会话时取消；
- 会话内联卡片（单题、无分页）+ 已回答折叠态；
- 4 语文案；
- 系统提示约束。

### P1

- 多问题分页、多选、推荐项默认选中；
- 未在视口时的胶囊提示 + 滚动定位；
- 子代理禁止调用 + 父级汇总提示；
- 追问/连续多次提问的节流（同一轮最多 2 次）。

### P2（可选）

- timed 模式（到点放行、后补答案）；
- 回答后作为一条 user 消息补进上下文（对齐 DSH 的 late reply）；
- 本地通知（App 在后台时提醒"有个问题等你回答"）；
- 问答历史检索（"我当时选了什么"）。

## 六、验收清单

- [ ] 模型调用一次 `ask_user`，卡片出现在消息流里，输入框不受影响
- [ ] 单选/多选/自定义输入/跳过 四种路径都能得到正确 JSON
- [ ] 点停止：卡片立刻变灰，工具返回 cancelled，无悬挂 continuation
- [ ] 杀掉 App 重进：待答卡仍在，答完能续跑（复用现有检查点）
- [ ] 子代理调用被拒，且父级最终结果里出现该问题
- [ ] 超时：卡片变灰 + 模型收到明确结果，不卡死
- [ ] 4 语下卡片不溢出、不裁切（中文/日文最长）
- [ ] VoiceOver 能读到问题、选项、选中态
- [ ] 长会话里插入问答卡后，高度/滚动不跳（复用现有行高体系）

---

## 七、需要你拍板的 3 个决策

1. **超时后模型怎么办**
   - A：默认 10 分钟，超时按"跳过"继续（推荐，iOS 上最不容易卡死）
   - B：一直等，直到用户回答或点停止（DSH 的 blocking 语义）
2. **回答入口**
   - A：消息流内联卡片 + 视口外胶囊提示（推荐，不打断输入）
   - B：像 DSH 那样临时占据输入框位置（更醒目，但要处理输入法/附件栏）
3. **是否允许子代理问用户**
   - A：禁止，必须回传给父级（推荐，DSH 同款）
   - B：允许，但弹窗注明"来自子代理 X"

## 八、工作量预估（不含调试真机手感）

| 阶段 | 内容 | 预估 |
|---|---|---|
| P0 | 工具 + Broker + 卡片 + 文案 + 提示 | 1.5～2 天 |
| P1 | 分页/多选/提示/子代理约束 | +1 天 |
| P2 | timed / 通知 / late reply | +1 天 |

主要风险在两处：**等待把引擎挂住时的取消路径**（要覆盖停止/离开/删除/超时四种），以及**卡片插入后的行高与滚动**（会话页那套高度系统很敏感，建议直接复用现有 block 行，不新造渲染路径）。

### 本版未做（属于 P1/P2）

- 问题卡不在视口时的"等你回答"胶囊提示 + 滚动定位；
- 多题分页器（当前是**纵向平铺**所有问题，题多时卡片较长）；
- timed 模式（到点放行、后补答案）与本地通知；
- 关掉卡片后的"重新打开"入口（历史卡片本身就是入口，没有独立重开状态）。

### 真机验收建议

1. 让 AI 问一个选择题（例如"把这几个文件删哪几个"），确认卡片出现在消息流里；
2. 点选项 → 提交，确认 AI 继续且回复里用到了你的选择；
3. 点「跳过」，确认 AI 按自己的判断继续并说明假设；
4. 卡片还在时点停止，确认卡片变灰、AI 不再等待；
5. 重进会话，确认历史里能看到问答卡与你的选择。
