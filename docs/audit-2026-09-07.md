## 二、P1 详情

### 1. `list_dir` 沙盒逃逸（契约与实现不符）

工具对外声明的契约（xcstrings 原文）：

```
list_dir_tool_desc      "…路径必须为 /var/MiniClaw/... 绝对路径。"
param_abs_path_example  "绝对路径，必须以 /var/MiniClaw/ 开头"
```

实现却走宽松解析：

```swift
// FileSystemManager.swift:970 —— 注释已写明「外部 Agent 工具不得调用」
private func resolvePath(_ path: String, sessionID: UUID? = nil) -> URL {
    if path.hasPrefix("/var/MiniClaw/") { … }
    if path.hasPrefix("/") { return URL(fileURLWithPath: path).standardizedFileURL }  // ← 任意绝对路径放行
    return workspaceDir.appendingPathComponent(path).standardizedFileURL
}
```

对照严格版本（file_read / file_write / delete / document / plugin 全部走它）：

```swift
// FileSystemManager.swift:829
func resolveAgentPath(_ path: String, sessionID: UUID? = nil) throws -> URL {
    let normalized = Self.normalizeMiniClawURL(path)
    guard normalized.hasPrefix("/var/MiniClaw/") else {
        throw FileError.absolutePathRequired(path)   // ← 越界即抛错
    }
```

调用链唯一暴露点：`ListDirTool.execute` → `FileSystemManager.listDirectory`（FileTools.swift:81）。  
（`fileExists` / `directorySize` 也走 lenient，但调用方是 MemoryManager 与设置页，传内部虚拟路径，不受 AI 控制。）

- **触发路径**：AI（含被提示注入操纵的 AI）调用 `list_dir {"path":"/var/mobile/Containers/Data/Application/<AppUUID>/"}` → 列出 App 容器内目录结构。
- **判定**：契约说只能列 `/var/MiniClaw/`，实现能列任意绝对路径 → 应用层沙盒失效。定 P1 而非 P0：iOS 系统沙盒仍兜底，且只能列、读不了（`file_read` 严格），泄露限于文件名与目录布局。
- **修复方向**：`listDirectory` 改走 `resolveAgentPath`；`/var/MiniClaw/mounts` 根的虚拟挂载分支需保留（严格解析要求 `mounts/<name>` 两级，"mounts" 单级会回退空目录）。

### 2. 设置-后台页死键引用

// BackgroundSettingsView.swift:19-23
} header: {

### 3. `NetService.resolve` 主路径恒失效

```swift
// RemoteHostTool.swift:684-693
await withCheckedContinuation { (cont: CheckedContinuation<String?, Never>) in
    DispatchQueue.global(qos: .userInitiated).async {
        let service = NetService(domain: "local.", type: Self.bonjourServiceType, name: serviceName)
        service.resolve(withTimeout: timeout)
        cont.resume(returning: service.hostName)   // ← hostName 恒 nil
    }
}
```

与既有结论直接冲突：9739993 已实测确认「**NetService.resolve 依赖 runloop，global queue 上静默失败**」，并为此加了 NWConnection 兜底。4276293 换用 NetService 时把 dnssd 的闪退修掉了，却把这条已知无效的路径留成了主路径。

- **后果**：每次 Bonjour 解析先白等一个 timeout，再走兜底；功能可用（09-07 真机自愈验证过），但主路径是死代码且注释误导（注释称"同步阻塞、自带超时、无回调"，未提 runloop 依赖）。
- **修复方向**：二选一——放到自带 runloop 的专用 Thread 上跑，或删除主路径只保留 NWConnection 兜底。**需唐唐拍板**。

## 三、P2 详情

**4. APIKeyStore 静默失败**（APIKeyStore.swift:29-35）：`SecItemUpdate` 的 status 非 `errSecItemNotFound` 时直接忽略，`SecItemAdd` 返回值也丢弃，函数无返回值不 throws → Key 未写入但 UI 显示已保存。改为 throws / 返回 Bool 并让调用方提示。

**5. 索引 identity**（MessageBubbleView.swift:246）：`ForEach(Array(items.enumerated()), id: \.offset)`。中段插入段时后续 offset 移位 → 视图错位重配 + Markdown 重解析。子代理定 P1，主代理下调为 P2：作用域是单个气泡内的少数段，且流式以追加为主，不崩溃。

**6. 引擎未加锁可变状态**（AgentLoopEngine.swift:5-19）：`routingPlan` / `systemStable` / `systemVolatile` / `baseVolatile` / `forceThinkingOverride` / `activeRequestTask` 均无锁，而 `toolExecutionTasks` 与 `pendingToolExecutions` 已加锁。若主线程 cancel/pause 与后台 runLoop 并发访问，存在与 2026-08-11 同模式的 ARC 引用计数竞争。理论风险，改造成 actor 成本较高。

**7. 高度缓存"用完即弃"**（MiniClawKit/MessageCollectionCoordinator+Heights.swift:249）：`var throwaway: [String: CGFloat] = [:]`，每次估算都完整测量。这是**有意的正确性权衡**（注释解释：避免估算 2 行、实测 3 行导致的滚动抖动），不是缺陷；若要优化，须保留"估算也走精确测量"的语义。

**8. `remote_host_config_write_failed` 键缺失**（RemoteHostTool.swift:311）：配置写入失败时用户/AI 看到键名本身。

**10. 草稿跨会话残留**（ChatView.swift:159-171）：`restorePersistedState()` 只在有草稿时回填，无草稿时不清空 `inputText`。若 ChatView 实例在切会话时复用，会残留上一会话文本，且可能被 `persistDraft` 写进新会话的草稿文件。**取决于导航身份是否随 session 变化，需真机确认**。

**11. project.yml 重复键**：`settings.base.OTHER_LDFLAGS` 定义了两次（`-Wl,-w` 与 iSH 静态库），YAML 后者覆盖前者 → 抑制链接器版本警告的那条实际未生效。

**12. 流式文本增长在滚动期被 defer**（MiniClawKit/MarkdownTextView.swift:1688-1720）：`isDeferred`（用户滑动中）时，只有「图片附件 + 增长 >30pt」豁免重测，**纯流式正文增长一律跳过**，0.6s 后 `pendingDeferredRemeasure` 才补测。期间气泡高度滞后、尾部可能被裁，滑动停止后"跳一下"补正。这与记忆 §12 记录的潜在隐患同源——豁免确实存在，但只对图片场景生效。**属设计权衡**（放开会让滚动期频繁重排，正是 `deferSelfSizing` 要避免的），建议先真机确认是否有可见跳动再决定。

**13. 输入栏重复残留**（ChatInputBar.swift:699-729）：两个空实现 `.onChange(of: focused.wrappedValue) { }`（注释完全相同）+ 两段逐字相同的 `.simultaneousGesture(DragGesture...下滑收键盘)`。分别挂在 TextField 与外层容器上，行为幂等无功能影响，但属复制残留，后续修改易分叉。

**14. `refresh()` 节流判定位置**（MiniClawChatBridge.swift:90-227）：先执行 `messages.sorted{}`(:90) + `sorted.map{bridgedMessage}`(:118) + 指纹遍历(:210-224)，最后才在 :226-227 判节流提前返回。0.25s 节流挡住了昂贵的 diffable apply，但挡不住每个 token 触发的全量排序/映射；超长会话流式期主线程 O(n log n) 持续。修复方向：用轻量指纹（`count` + 末条 `content.count` + `isResponding`）在排序前快速短路。

## 四、已证伪（不建议改）

**HealthKitTools continuation 无超时**（HealthKitTools.swift:114）：子代理报"回调不触发则 Task 永久挂起"。`HKHealthStore.requestAuthorization` 的回调由 Apple 的 API 契约保证触发，属理论风险，加超时反而引入复杂度。

**高度缓存键含 `String.hashValue`**（MiniClawKit/…Heights.swift:100）：

```swift
let key = "\(text.count)|\(Int(usableTextWidth))|\(Int(fontSize))|\(attachCount)|\(text.hashValue)"
```

报"每进程随机 + 非无碰撞 → 可能命中错误高度"。`hashValue` 确为每进程随机种子，但**进程内稳定**，而该 cache 是内存字典、不跨启动复用，故缓存正常工作；64 位碰撞概率可忽略。属理论风险。

**发送后 300ms 防抖覆盖注入草稿**（ChatInputBar.swift:221）：报"performSend 排程的空串任务会覆盖随后注入的文本"。实际 `.onChange(of: injection)` 第一行即 `draftSyncTask?.cancel()`，已取消挂起的防抖任务，随后 `draft = newText` 立即同步。无竞态。
