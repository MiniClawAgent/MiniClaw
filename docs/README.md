> 判断「现在是什么状态、还有什么没做」只看两份文件：`CURRENT_STATE.md` 与 `ISSUES.md`。
> 其余报告要么是**仍在维护的参考**，要么是**只读历史归档**。

## 3. 历史归档（只读）

`archive/` 存放已被取代的一次性报告，**不再维护、不得据此判断现状**。
索引与归档原因见 `archive/README.md`。

归档纪律：

1. 一份报告被新文档取代后，**移入 `archive/` 并在 `archive/README.md` 登记**，不留在顶层。
2. 归档文件内容**不再修改**；如需修正结论，写进 `ISSUES.md` 或新报告。
3. 归档报告内部的路径引用（`Doc/...`、旧 `docs/...`）是**当时布局**，迁移后不保证可点。

---

## 4. 新增文档的规矩

- 命名：`YYYY-MM-DD-主题.md`（日期用报告完成日）；专题规格用 `主题.md` 放对应子目录。
- **一次性报告完成后直接进 `archive/`**，不要堆在顶层。
- 报告里出现「已修复」的结论时，必须在 `ISSUES.md` 里同步关闭对应条目，避免两份清单打架。
- 修改 `docs/` 之外的文档（如 `ENGINEERING_DISCIPLINE.md`）时，检查本索引是否失效。
