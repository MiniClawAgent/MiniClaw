- **建议**：先真机确认是否真的看得见跳动，再决定动不动。**不要盲改**。

## 四、安全与隐私

### ⑤ `list_dir` 能列出沙盒外的目录
- **位置**：`Tools/FileTools.swift:81` → `Services/FileSystemManager.swift:970`
- **事实**：工具描述明确对 AI 声明"路径必须为 `/var/MiniClaw/...` 绝对路径"，但实现走宽松解析，**任意 `/` 开头的绝对路径直接放行**。而 `file_read`/`file_write`/`delete` 全走严格版（强制前缀、越界抛错），只有它被漏掉。
- **AI 能做什么**：`list_dir {"path":"/var/mobile/Containers/Data/Application/<App>/"}` → 列出 App 容器内目录结构（数据库、日志、缓存、配置的文件名与布局）。
- **不能做什么**：读不了内容（配合 `file_read` 被严格版挡住），也出不了 iOS 系统沙盒。
- **实际风险**：中等。主要是**信息泄露 + 契约与实现不符**；触发需要 AI 主动或被提示注入引导。定 P1 而非 P0 就是因为系统沙盒兜底、且只能列不能读。
- **修复注意**：改严格解析时必须保留 `/var/MiniClaw/mounts` 根的虚拟挂载分支（严格版要求 `mounts/<name>` 两级，单级 "mounts" 会回退空目录）。

## 五、数据可靠性

### ⑥ API Key 可能"存了但没存进去"
- **位置**：`Services/APIKeyStore.swift:29-35`
- **用户遇到什么**：在服务商页填了 API Key、UI 显示已保存，实际 Keychain 写入失败（返回值被丢弃，函数不 throws）→ 下次请求直接认证失败，用户困惑"我明明填了"。
- **频率**：低（Keychain 一般不失败），但失败时**完全静默**，无任何提示，排查成本很高。

### ⑦ 草稿可能串到别的会话（待真机确认）
- **位置**：`Views/Chat/ChatView.swift:159-171`
- **理论后果**：切换会话时若 ChatView 实例被复用，上一会话未发送的输入会残留，并可能被写进新会话的草稿文件。
- **状态**：**取决于导航身份是否随 session 变化**，静态分析无法确定。建议真机验一次：在 A 会话打几个字 → 切到 B 会话 → 看输入框是否残留。

### ⑧ 远程主机解析每次白等一个超时
- **位置**：`Tools/RemoteHostTool.swift:684-693`
- **影响**：Bonjour 解析主路径（NetService）在 global queue 上**恒失效**（与你们 9739993 实测结论一致：它依赖 runloop），实际全靠 NWConnection 兜底。功能可用（09-07 真机自愈验证过），但每次解析先空等一个 timeout，且代码注释在误导后来人。
- **需你拍板**：是让 NetService 跑在带 runloop 的专用线程上，还是干脆删掉主路径只留兜底。
