## 0 结论摘要

MiniClaw 是一款 **本地优先的 iOS 通用智能体应用**：把「大模型接入层 + 内置 Alpine Linux 运行环境（iSH/AArch64）+ 40 个工具 + 会话级文件隔离 + 块级流式渲染」整合进一个 App。工程已到 **v1.0 build 9**，处于**上架前收尾**阶段，功能面基本封板，当前主要精力集中在 **会话渲染管线的正确性**上。

五条最该记住的事：

1. **工程只有一棵代码树进 git**，但**源码有两棵**（`MiniClaw/MiniClaw/` + `MiniClaw/MiniClawKit/`），全库扫描必须两棵都查，否则整棵漏检。

## 2 构建与验证

### 2.1 本会话实测（重要）

团队文档的标准命令在本会话沙箱下**有两个不可用点**，我踩到并解决：

| 问题 | 现象 | 解法 |
|---|---|---|
| `-alltargets` 与 `-derivedDataPath` 互斥 | `error: The flag -scheme, -testProductsPath, or -xctestrun is required when specifying -derivedDataPath` | 改用 `-scheme MiniClaw`（连带构建 Widget + ShareExtension） |
| module cache 不可写 | `unable to write module session file at /var/folders/.../ModuleCache.noindex/...: Operation not permitted` | 把 `CLANG_MODULE_CACHE_PATH` / `SWIFT_MODULECACHE_PATH` / `MODULE_CACHE_DIR` 全部重定向进工程外工作区目录 |
| DerivedData arena 不可写 | `Failed to create workspace arena at ~/Library/Developer/Xcode/DerivedData/...` | 必须显式 `-derivedDataPath <工程外>` |

**可用命令（本会话已验证 → `** BUILD SUCCEEDED **`）**【核】：

```bash
cd MiniClaw
CLANG_MODULE_CACHE_PATH=$WS/.xcode-sym/modulecache \
SWIFT_MODULECACHE_PATH=$WS/.xcode-sym/modulecache \
xcodebuild -project MiniClaw.xcodeproj -scheme MiniClaw \
  -destination 'generic/platform=iOS' -configuration Debug \
  CODE_SIGNING_ALLOWED=NO \
  SYMROOT=$WS/.xcode-sym OBJROOT=$WS/.xcode-sym/obj \
  -derivedDataPath $WS/.xcode-sym/dd \
  MODULE_CACHE_DIR=$WS/.xcode-sym/modulecache \
  OTHER_SWIFT_FLAGS="-Xfrontend -disable-sandbox" build
```

> 本次验证的产物（`dd` / 构建日志）已清理，只保留 `obj` + `modulecache` 供后续增量编译。重建时 `dd` 会自动重建。

### 2.2 两条硬约束

1. **不跑 `xcodegen generate`** —— 入库 pbxproj 与 `project.yml` 漂移，重生成 = cmark 模块遮蔽编译错误 + 默认 destination 变模拟器。增删/移动文件用 Python 直改 pbxproj，删文件用 `XcodeRM`。
2. **模拟器 destination 必然失败** —— iSH 静态库是 arm64 device-only；报一大片 `Undefined symbol: _fakefs/_do_execve/...` 属环境限制，不是代码问题。

## 4 Agent 执行内核

主文件 `Services/AgentLoopEngine.swift`（2516 行）【抽，关键点已核】。

### 4.1 主循环

`runLoop()` 外层 `while true`，每轮：**安全点 0（退后台宽限期等待）→ 安全点 ①（暂停检查）→ 轮数守卫 → 端点遍历 / 重试双层 → 工具分类 → 伪完成兜底 → 无工具则收尾 → 无效工具熔断 → 追加 assistant + 落检查点 → 并发执行工具 → 空转断路器 → 重建 volatile → 逐条落 tool 结果 → 安全点 ②（暂停检查）→ 工具连续失败熔断 → 提示注入**。

**关键顺序约束**：提示注入（空转 warn / 检索收敛提示，都是 `role=user`）**必须晚于全部工具结果落盘**，否则打断 `assistant(tool_calls) → tool…` 紧邻关系 → 端点 400（真机 2026-09-11 有实证）。

### 4.2 停止与熔断条件

| 条件 | 阈值 | 结果 |
|---|---|---|
| 迭代轮数 | **50** | `iterationLimitReached` |
| 连续「仅无效工具」 | 2 轮 | 可见提示 + 中断 |
| 同「工具名 + 归一化参数」失败 | 2 次 | 熔断（忽略每轮都变的 call id） |
| `ToolLoopBreaker` 空转 | genericRepeat 6/10、pollRepeat 6 | 中断 |
| 检索收敛预算 | 12 次工具调用 | 注入一次收敛提示（不强制终止） |
| LLM 自动重试 | **5 次 × 3s** | 耗尽则 `emitError` |
| 用户暂停 / 取消 | — | 暂停可恢复；取消直接 return |

**已刻意移除单轮总墙钟上限**（注释：真机「生成招标文件 8 轮 browser + 10 轮 file_write 被 300s 硬砍」）。防挂死改由三层分摊：LLM 网络（30s 无数据 / 120s 总时长）、各工具自带超时、循环熔断。

### 4.3 伪完成自愈（3 条，各带次数上限）

| 触发 | 处理 | 上限 |
|---|---|---|
| `finish_reason ∈ {length, max_tokens}` 且正文**或思考**非空 | 续写提示 | 3 轮 |
| `finish_reason == tool_calls` 但 0 有效工具 | `sys_tool_calls_mismatch` | 1 轮 |
| 正文空但思考非空 | `sys_empty_reply_continue` | 1 轮 |

> 第 1 条曾因只判 `!text.isEmpty` 而在「深度思考写满 max_tokens、正文为空」时跳过续写 → 真机表现为「思考 3K 后正文消失」。修法是条件加 reasoning 非空。

### 4.4 检查点与恢复

- **权威真源 = `AgentTask.messages` 全量循环上下文**。**不能**从会话历史重建 —— ChatView 构建时会过滤掉 tool 角色，`tool_call ↔ tool_result` 配对无法还原。
- 存储：SQLite `session_blobs`，`kind = .agentTask`；排队消息另存 `.pendingQueue` / `.pendingDraft`（**磁盘真源是 `PendingMessageStore` 而非检查点**）。
- 落盘时机：每轮 assistant 回合后写 `.running`；暂停安全点写 `.paused`；终态由调用方 clear。
- **活跃性不变量**：`saveCheckpoint` 三重守卫 `!isSubagentEngine && sessionID != nil && keepRunning()`。否则 `cancel()` 先 clear、后台循环后写，磁盘残留 `.running` → 下次进会话被当成「被中断任务」**自动续跑（已取消的回复复活）**。
- **子代理引擎不写检查点**：它复用真实 sessionID，会把后台对话写进 `AgentTaskStore[真实sessionID]` → 后台消息冒泡到用户对话框。

### 4.5 线程模型

| 机制 | 内容 |
|---|---|
| 状态保护 | `actor EngineState`（cancel/pause/pendingUserInputs/retryNow）+ NSLock 的 `pendingToolExecutions`（锁内只做字典取写，回调一律锁外）+ `ToolTaskBag` |
| UI 回调唯一出口 | `deliverOnMain` = **一律 `main.async`，绝不 `main.sync`，且刻意不做 `isMainThread` 短路**（短路会让主线程调用插队到已入队回调之前 → token 与 toolResult 乱序） |
| 工具体执行 | `Task.detached(priority: .userInitiated)`（真机曾 MAIN THREAD BLOCKED 39.9s / 51.6s） |
| 作用域注入 | TaskLocal 三个：`ToolEngineScope`（当前引擎，父子共享 router 时防固定 weak 引用解析错引擎）/ `ToolProgressScope`（过程流）/ `EngineBrowserScope`（浏览器隔离） |
| 配置读取 | 后台线程**一律** `MainActor.run` 快照后再读（2026-08-13 后台裸读的 EXC_BAD_ACCESS / COW 悬垂教训） |

## 5 工具系统

### 5.1 协议与路由

```
protocol AgentTool {
  name / schema / execute() async throws -> ToolResult
  resumePolicy: ResumePolicy      // 默认 .retryable
  executionTimeout: TimeInterval? // 默认 120s
  activityParameterName: String   // 默认 "activity"
}
```

- **`ResumePolicy` 在 v1 只是元数据**（暂停只在安全点生效，恢复是整轮回放）。真正生效的确认门是全局 `defaults.confirmBeforeToolCall`，**默认 false**。
- `ToolRouter.allSchemas()` **必须按工具名排序** —— 2026-09-15 治本：Swift 字典遍历顺序不稳定（跨进程哈希种子随机）→ tools 段排列抖动 → 整段前缀缓存失效。真机实证：同会话内指纹恒定、每换任务即变。
- **随角色变化的工具必须排最后**（`read_subagent_result` / `dispatch_subagent` / `close_subagent`），否则按字母序夹在共享工具中间，其后所有工具定义落在不同前缀上，主/子、子/子缓存复用全失效。

### 5.2 注册三条路径（判死代码必须穷举）

### 5.4 子代理机制

| 维度 | 设计 |
|---|---|
| 深度 | `maxSubagentDepth = 2`；主引擎恒可派发；**受限后台引擎（复盘/记忆整理）不可派发**（否则无人值守地凭空派生并继承写工具） |

## 6 模型接入层

### 6.1 适配器与协议差异

`LLMProviderAdapter` 是薄协议（认证 + 请求构造 + 流式解析 + 能力声明）。**加新厂商 = 新建一个文件 + 工厂注册一行**。

| 适配器 | 覆盖厂商 | 端点 | 认证 | 关键差异 |
|---|---|---|---|---|
| `OpenAIProviderAdapter` | openai / openRouter / custom / grok / deepSeek / qwen / xiaomi / zhipu（**8 家共用**） | `v1/chat/completions`；`apiFormat == .responsesAPI` 时走 `responsesPath` | `Authorization: Bearer`（Azure 用 `api-key`） | 行为由 model 插件 `behavior` 声明驱动；`cacheStableEncoder`(.sortedKeys) |
| `AnthropicProviderAdapter` | anthropic | `v1/messages` | `x-api-key` + `anthropic-version: 2023-06-01` | **三段 `cache_control` 断点**；连续 `tool_result` 必须合并进同一条 user 消息（否则 400）；529 → rateLimited 可重试 |
| `GeminiProviderAdapter` | google | `v1beta/models/{model}:streamGenerateContent?alt=sse&key=` | query `key` | system→`systemInstruction`；**无终帧哨兵，连接正常关闭即成功**（绝不能报 streamTruncated）；安全设置 5 类全 BLOCK_NONE |

**流式解析三个 delegate 的共同质量**：Data 级行缓冲（UTF-8 跨 chunk 不丢字）、1 MiB 缓冲上限、64 KiB 错误体上限、唯一终态出口（幂等守卫 + `finishTasksAndInvalidate`）、**失败也先回传 finishReason 与 usage**（续写兜底依赖）。

### 6.2 能力表（`ProviderType`，单一事实来源）

| 能力 | 事实 |
|---|---|
| `responsesPath` | deepSeek = `"responses"`（官方无 `/v1` 前缀）；zhipu/anthropic/google = nil；其余 = `"v1/responses"` |

### 6.3 缓存策略 —— 全码主线约束

1. 请求体编码一律 `.sortedKeys`（曾因字典键序漂移导致 8176 tok 工具目录命中率为 0）。

4. `CachePrefixFingerprint` + `[Cache命中]` 配对诊断；`MiniClawTests/CacheStabilityTests.swift` 守三条铁律。

## 8 会话渲染管线（当前最热区）

### 8.1 结构：四层嵌套

```
MiniClawApp → ContentView(NavigationStack) → HomeView(SwiftUI List)
                        ↓ appState.selectedSession
ChatView(SwiftUI 外壳)
  └ MessageCollectionView (UIViewRepresentable)
      └ MessageListViewController
          ├ NoAnimationCollectionView + MessageListLayout(自研 flow，非 compositional)
          ├ UICollectionViewDiffableDataSource<Section, MessageListItem>
          └ SelfSizingCell + UIHostingConfiguration { BridgedAssistantBlock … }
               └ MarkdownView (UIViewRepresentable)
                    └ MarkdownTextView (UITextView + TextKit1 + 自定义 LayoutManager)
```

**item 是块级的**：一个 assistant 轮次 = `assistantHeader` + N×`assistantBlock` + `assistantFooter`；用户/系统消息是单个 `wholeMessage`。

**为什么必须桥到 UIKit**（代码结构可证的四条）：异构自 sizing cell（4pt ~ 1700pt+）；布局层必须可干预（手势期冻结 / 解冻原子落盘 / offset 补偿 / 宽度专属失效——SwiftUI `List/ScrollView` 无对应物）；稳定身份 + `reconfigureItems` 定向重配；流式高频局部刷新（就地改写 + `invalidateLayout`，不 apply snapshot）。

### 8.2 高度体系（已收敛的部分）

| 机制 | 内容 |
|---|---|
| 单一写入口 | `HeightEntry{height, source, key}`；`setEntry` 唯一写入；优先级 `measured > precalc > estimated`，**低不覆盖高**，且**按 `currentEntry` 判**（内容已变的陈旧条目可被覆盖） |
| 内容版本感知 | `currentEntry(at:)` 键不一致即**视同无条目**（demote 陈旧条目）——「上滑回看裁尾」的治本点 |
| 三个唯一出入口 | `seedHeights(SeedScope)`（播种）· `invalidateHeight(memo:)` + `remapHeights`（失效/迁移）· `applyDeferredHeights()` / `takePendingAboveShift()`（结算） |
| 引擎下限 | `engineFloor = engineTextHeight + 4`，**下限不得含 cell 当前高度**（含则 1365→1455 跑飞） |
| 宽度单一事实源 | `blockHPadding = 16` → 内容宽 = cell 宽 − 32 |
| Single height source | `commitHeight` 是唯一高度提交出口，把 `h − chrome` 记入 cell；`MarkdownView.sizeThatFits` 侧当 **floor** 用（三道校验：指纹 / 宽度 / rawMarkdown 指纹） |
| 估算同源 | 估高必须与渲染形态同源；用户气泡高度必须走 cmark 管线测 |

## 9 运行时容器 / 文件系统 / 浏览器 / 扩展

### 9.1 iSH 嵌入式 Linux

| 项 | 事实 |
|---|---|
| 形态 | AArch64 guest + **Asbestos 解释器**（threaded-code，**非 JIT，无需特殊 entitlement**）；x86 后端并存 |
| 产物 | `libish.a` / `libish_emu.a` / `libfakefs.a`（device-only）+ `cpu-offsets.h`（信号恢复用寄存器偏移） |
| rootfs | Alpine **3.24**，部署到 `Library/Application Support/MiniClaw/ish-rootfs`；四文件校验（meta.db / bin/sh / bin/busybox / ld-musl-aarch64.so.1），防中断拷贝被误判为已部署 |
| 启动 | 10 步严格有序：信号处理器 → `mount_root` → 首进程 + `current->thread` → /dev 节点 → `exit_hook` → proc/devpts → `/var/MiniClaw` bind mount（+ guest 侧 mkdir 保底）→ 挂载占位/镜像同步 → **会话路径 hook** → DNS 重写 |
| 重试 | 串行队列取代 `dispatch_once`（失败可重试）；但**内核状态不可复位**，重试只是 best-effort |
| 恢复出厂 | 不能进程内做（iSH 不支持卸载/重挂根）→ 只写 UserDefaults 标记，下次启动 deploy 最前端删旧重拷 |

### 9.2 会话文件隔离（本项目对 iSH 最深的定制）

- `SessionFileRouter` 为每个会话分配 `fs_context`（进程内递增，不持久化，`0` = 无会话/系统进程）。
- 宿主目录 `Documents/MiniClaw-Sessions/<uuid>/{workspace,attachments,browser,offloads,subagent}`，**刻意放在父 bind mount 树之外**（否则反查被静态挂载表劫持）。
- 正向 hook 只接管 5 个会话子目录前缀，调 `@_cdecl` 回 Swift 解析；反向 hook 供 `realfs_getpath`（`ls`/`getcwd`）。
- 路径自带 uuid 时校验「路径 uuid == 当前 fs_context 所属会话」→ **防跨会话越权**。
- `ensureHostDirs` **拒绝 staging+rename**（会在 base 已存在时先删再搬空目录 → 重启后清空会话 workspace）。

### 9.3 挂载（**不是真 mount**）

iOS 沙盒无法真挂载 → `MountStore` 用 app-scoped bookmark + 逻辑映射 + **带账本的双向镜像**（v2）。
- v1 按 (mtime,size) 较新覆盖 → **乒乓循环**（每 20s remove+重写全部文件，iSH ls 读到空目录）。
- v2 每文件记 `{extSize,extMtime,mirSize,mirMtime}`，只有相对账本变化才同步；`.atomic` 写入**绝不先 removeItem**；外部读取用 `NSFileCoordinator(.forUploading)` 物化 File Provider 文件。
- **返回值不做 `standardizedFileURL`/`resolvingSymlinksInPath`**（File Provider 是虚拟化路径，标准化会脱离 security scope → 镜像永远为空、iSH `cat` 退出码 256）。
- 挂载默认 `isWritable = false`（只读），写入由 `validateWrite` 拦。

### 9.4 浏览器

WKWebView 封装 + 标签池（会话 1–5 / 全局 8）。**旧 `BrowserController` 体系已于 09-15 整体 git rm（~1780 行），现在只有一套**：`MiniClawTabPool` + `MiniClawBrowserEngine`（数据）→ `BrowserEngineAdapter`（UI 接口 + agent run 入口 + 串行门 + 取消托管标记）。
- 唯一 UA 事实源 = 池的 `MiniClawUAProfile`；历史只此一套（引擎 `didFinish` 写 `MiniClawHistoryStore`，UI 侧**不要**再补订阅）。
- Cookie 是**全局共享**（`.default()` dataStore）——会话隔离在引擎侧从未生效，属已知设计现状。

## 10 工程纪律（我会遵守）

**产品纪律（唐唐硬性）**：未上架=零兼容（禁迁移器）· **治本不补丁**（S5 四问）· **最少代码** · 不自由发挥 · **零第三方痕迹**（代码/注释/文档/UI/i18n/测试名全算，指代一律「上游 / 参考实现」）· 同类 UI 控件收敛共享组件 · 报告＝分章节＋对比表＋逐行源码对比＋验证清单。

**流程纪律**：改完必自验 `BUILD SUCCEEDED`（B1）· 产物在工程外（B2）· 架构改动先给影响分析 · **没有阻塞的事必须同轮做完**，禁「只声明不执行」· 探针/日志等不影响功能的一律直接加，不占用轮次。

**排查纪律**：先定位根因证据再改码（Q1）· 单一修复只解决一个问题（Q4）· **同一问题修 3 轮以上仍复现 ⇒ 质疑判据本身、换观测量**（09-14 的「stale render」正是换观测量后 7 次命中）· **现象实证 ≠ 成因实证**，报告里必须分开表述。

**工具纪律**：BSD grep 不支持 `\|` 交替（**静默漏检**，曾致「零残留」误判）→ 一律用 Grep 工具 + 编译兜底 · 同一文件的多处 Edit **必须串行**（并行会静默丢改动而工具仍报 success）· zsh 会展开 `--include=*.swift` glob。

**数据/编码纪律**：外部 JSON 解码显式 `init(from:)` + 全字段 `decodeIfPresent`（防旧数据缺键导致整域回退默认并覆盖落盘）· 自定义 `init(from:)` 会顶掉合成 `init()` → 显式补 `init() {}` · xcstrings 用 Python json 往返 + **绝不整表重排** · `String(format:)` 格式符逐一核对（错配编译通过、运行期 SIGSEGV）。
